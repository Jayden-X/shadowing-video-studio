# Local video runtime

The fixed template consumes the current reviewed sentences and their exact ready speech
asset bindings. It produces 1920x1080, 30 fps H.264/AAC MP4: one sentence per page, left
English text, a reserved visual area on the right and a dynamic waveform at the bottom.
Each page includes a five-second silent pause after speech, including the final sentence.
Text is wrapped using the configured font's metrics; missing glyphs or text that cannot
fit are rejected with a request to edit/split the sentence, never silently truncated.

## Setup

Configure [local speech](speech-runtime.md) first. In the ignored root `.env`, add existing
absolute executable/font paths:

```dotenv
VIDEO_FFMPEG_EXECUTABLE=/absolute/path/to/ffmpeg
VIDEO_FFPROBE_EXECUTABLE=/absolute/path/to/ffprobe
VIDEO_FONT_PATH=/absolute/path/to/font.ttf
VIDEO_TIMEOUT_SECONDS=600
FRONTEND_DIST_DIR=/absolute/path/to/frontend/dist
```

Use a FFmpeg build with `drawtext` (FreeType/Harfbuzz), PNG decoding/image2pipe, H.264/AAC encoding,
and the other fixed-template filters. An executable path alone does not prove these
capabilities. The target Mac's `/opt/homebrew/bin/ffmpeg` build lacks `drawtext` and cannot
render this template. The Arial font is `/System/Library/Fonts/Supplemental/Arial.ttf`.
Readiness and submission perform bounded capability queries, with successful results cached
only while the resolved FFmpeg/ffprobe executable fingerprints remain unchanged. Missing
capabilities prevent job creation and report how to correct the configured build.
The optional `drawtext` `text_shaping` setting is disabled when the build supports it;
builds without that option omit it because their corresponding FriBidi shaping feature is
absent. Required text-file/font/expansion/layout options are always checked. See the
[FFmpeg source](https://github.com/FFmpeg/FFmpeg/blob/n7.1/libavfilter/vf_drawtext.c).
Existing tools and fonts are read in place; this feature does not install global tools or
modify fonts. Generated files and temporary files
remain under the configured speech workspace inside the approved project/cache directory.

For a source checkout, build the frontend with `npm ci && npm run build` in `frontend/`.
From `backend/`, start one local service:

```bash
uv run --env-file ../.env uvicorn shadowing_video_studio.main:app \
  --host 127.0.0.1 --port 8765 --workers 1
```

Open `http://127.0.0.1:8765`. It serves the built frontend and API together. The development
Vite launcher continues to work. Double-click packaging is still a separate decision.

## Workflow and API

Review sentences, explicitly generate/preview speech, then choose **Generate video** when
all current sentences have matching ready audio. Editing text invalidates its old binding.
Render progress and safe failure messages are shown. Failure preserves speech and previous
exports; retry is explicit. Stopping browser monitoring does not claim to cancel rendering.

- `GET /api/video/status`: configuration/tool capability readiness without invoking encoding.
- `POST /api/video/jobs`: frozen ordered `[{id,text,assetId}]` and an opaque job ID.
- `GET /api/video/jobs/{id}`: progress and completed/failed state.
- `GET /api/video/assets/{id}`: local MP4 preview with Range support.
- `GET /api/video/assets/{id}?download=true`: download attachment.

Speech and video share one process-local heavy-job gate. Use one ASGI worker. Media routes
require local loopback Host/Origin. No client filesystem input/output path is accepted.

The render owns a fresh `video/<opaque-id>/` directory and immutable private WAV snapshots.
Font, text and media filenames inside FFmpeg commands are generated by the application;
source text is passed in a text file with expansion disabled. Intermediate pages use H.264
and PCM; the final concat encodes AAC once to avoid adding encoder delay per sentence.
Timeout/cancellation reaps the owned process group. Failure evidence is retained locally,
without putting raw source text or FFmpeg diagnostics in API errors.

Current resource limits: ten minutes per video including pauses, 64 MiB of WAV snapshots,
128 MiB per final MP4, 512 MiB per job directory, twenty jobs and 2 GiB per service session.
The renderer checks the input/minimum output budget before copying or encoding, recalculates
remaining space per page, and bounds every FFmpeg output with `-fs`. A 4 MiB packet/footer
margin is reserved; FFmpeg may slightly exceed `-fs`, so this is a preventive limit rather
than an operating-system disk quota. An output at the limit is rejected and never published
as a truncated export. Final size, format and duration checks still apply.
Failed attempts retain their reservation. No automatic overwrite, pruning or deletion occurs.

Task008 records project-bound completed exports and frozen inputs in local SQLite metadata.
Historical outputs remain accessible after edits/restarts when their recorded bytes validate;
current TTS availability is not required for historical MP4 playback. Unregistered legacy
exports remain preserved without automatic history import. See [project history](project-history.md).

## Reference frequency bars (Task 011)

The renderer streams transparent 1260 × 180 PNG layers directly into the page's FFmpeg
process and overlays them at (0, 850). Each layer has 36 black rounded bars starting at
x=118, with 29 px pitch, 16 px width, 7 px corner radius and maximum 145 px height centered
at y=90. There is no waveform backplate. The default background is light blue with dark
text; uploaded backgrounds keep their dim layer and white text. Black bars may be hard to
see on dark uploads, so choose a light background.

The project-owned standard-library analyzer uses frozen 24 kHz mono PCM16 WAVs, 800-sample
Hann windows at 30 fps, a 2048-point FFT and 36 logarithmic bands from 80 to 8000 Hz.
Per-band RMS magnitude is square-root normalized by the strongest band, combined with
`min(1, audio_rms * 9)`, and mapped to the reference heights. RMS <= 0.001 yields a fully
transparent frame. Frames after audio EOF, including the five-second pause and any final
frame quantization padding, are transparent. A partial final audio window is zero-padded.

Eight-frame batches are computed off the event loop and written with pipe backpressure.
Only a bounded batch/frame is held in memory; there are no frame files or new dependencies.
The existing page process owns encoding, timeouts, cancellation and output size limits.
Capability preflight checks PNG decoding and image2pipe rather than requiring showwaves.
EOF and exceptions in the input stream still use the existing owned-process cleanup.
